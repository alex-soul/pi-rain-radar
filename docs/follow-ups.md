## Previously tracked 0.5.0 scope — pending release reconciliation

Open work to pick up after 0.4.0. These items do not block this release.

- [ ] **Live and Archive playback.** Correct observation-time playback in both modes and adopt the agreed naming convention. See the [next-release requirements](#live-and-archive-playback).
- [ ] **Archive-only map provider names.** Add an option in the Archive date-picker popup to show the actual displayed observation's provider at the top right of each map. Keep it clearly readable without obstructing the map; it need not be tiny. Do not add a Live option or show this overlay during Live playback. Keep footer attribution independent. Default disabled; hide on every return to Live, whether manual or by countdown. The switch is nonpersistent; each new Archive visit starts disabled. Confirm final design and placement during local build/test, including other overlays and source changes.
- [ ] **Conditional Rainbow Save and Apply prompt.** After successful initial key insertion, if provider selections were also changed and remain unapplied, offer a confirmation popup to Save and Apply now. Do not apply silently. If no provider changes are pending, show only "Configured" without a popup. Exact copy, cancel behaviour and later key-replacement handling remain to be refined.
- [ ] **Prolonged Pi soak — deferred until after the next release.** Further potentially performance-impacting changes are coming; endurance/stress testing will follow the release, not gate it. Retain the intended several-hour/overnight split-provider, six-hour/full-speed checks for memory growth, swapping, freezes, recovery, history and request-counter persistence. Routine change-specific validation remains required; good observed experience is not a completed soak.
- [ ] **Confirm snapshot billing — no earlier than November 2026.** Revisit after a full billing cycle to determine whether Rainbow snapshot checks count against the free allowance. Keep current estimates explicitly conditional until verified.

- [ ] **Touch-friendly gust-cache picker.** Replace the local numeric input with a tap-operated picker: 0, 15, 30, 45, 60, 90, 120 and 180 minutes; default 60. Zero disables retained gust fallback, not the gust reading itself. Explain zero in tap-accessible help. Keep supported saved values; map valid legacy positive values to the nearest positive choice (lower on ties, cap 180), with absent/invalid values defaulting to 60. Do not migrate a positive value to Off. All per-display settings must be usable without a keyboard; shared settings may be entered remotely.

## Live and Archive playback
- [ ] **Experimental Stats for nerds.** Add a configurable button hidden by default and a closed-by-default draggable/resizable widget. First slice: per-map provider/latest observation age, last/next check, acquisition state, selected-window completeness and local monthly Rainbow request/tile counts. Distinguish current acquisition from Archive selection and local counters from billed usage. Reuse status refresh, show stale/unreachable state, expose no credentials and require no host privileges. Process uptime/memory are optional; whole-host monitoring and graphs are outside this slice.
- [ ] **Archive windows up to 24 hours.** Add a temporary Archive slider, styled like playback speed, from 1 to 24 hours in whole-hour steps and defaulting to the display's saved Settings window. Discard it on every return to Live; Settings and Live retain 2/4/6-hour choices. Target a one-hour minimum; use two only if one proves disproportionately complex. Keep the existing available-date/time selectors; a calendar replacement is not required. Use retained data without extra provider acquisition merely to satisfy a longer viewing window. Review the current 37-position loader cap, load deadline, image memory, cancellation and fast scrubbing. Validate remote client performance and Pi serving/acquisition impact; smooth Pi-local 24-hour playback is not a release gate. Keep seven-day retention and honest partial-window gaps.
- [ ] **Optional PWA installation.** Bundle manifest/icons/standalone support in the normal app package, without a separate helper or feature switch. Preserve ordinary HTTP and kiosk use. Document installation discreetly in the manual, without in-app install banners or prominent promotion. Trusted HTTPS remains optional deployment setup for normal PWA installation; validate Android Chrome and Windows Chrome and describe HTTP shortcuts/manual installation only as actually observed. Check updates, reconnect and display preferences; no offline radar cache or notifications are included.


Separate UI requirements for this release:

- **Reference-screen Settings fit:** consistently wider Settings on the 1280 × 720 reference display; Readings uses two columns of five standard-height rows, ordered down the left then down the right, with touch reordering across columns. Ordinary pages should fit without scrolling; expanded optional detail may scroll. Other screen sizes are outside this fit guarantee; narrow phones can use one column and scrolling.
- **Settings inactivity:** close after five minutes without user activity, resetting on Settings interactions and related popups. Background polling must not reset it. Coordinate the browser timer and PIN session expiry so ongoing interaction remains authorized, while real inactivity locks the session. Apply the UI inactivity rule with and without a PIN. Current expiry is fixed from unlock and ordinary clicks/tab changes do not renew it.

- **Free widget placement:** Overview and Rain forecast may be placed anywhere within the screen, including behind either dock regardless of auto-hide. Dock expansion/collapse and settings changes must not shift or resize widgets. Docks stay above widgets; tuck a dock away to access covered widget controls. Adjust only as needed for viewport-size/orientation changes. This supersedes the earlier dock-collision proposal and removes the current footer-only boundary.
- **Bottom dock above attribution:** keep the entire dock, including its collapsed handle and touch target, above attribution. On narrow screens attribution currently can cover the handle. Verify collapsed/expanded states, both themes and tap access while preserving unobscured attribution links and modal layering.

Agreed for the next release; not implemented in 0.4.0. Follow the canonical [terminology and playback behaviour](playback-conventions.md). This replaces the earlier screen-recording interpretation of History.
